# 导入 Notion：页面结构、上传步骤、坑和核对

## 目标结构

```
📚 <考试名> · 复习资料（总入口页，来自 00_总览）
├── 01 分册页（册首说明 + 导言/符号对照）
│   ├── 第1章 …（子页面：知识点清单 → 核心内容 → 易错点 → 典型题，答案在绿色折叠块）
│   └── …
├── … 02–08 分册
├── 🗃 知识点进度（数据库）
└── 09 公式与常数速查（单页）
```

数据库字段：知识点（标题）/ 分册（单选）/ 章节 / 重要程度（★★★ 红、★★ 橙、★ 灰）/ 教材页码 / 掌握状态（状态：未开始 → 学习中 → 已掌握）/ 复习次数（数字）/ 备注。`md_to_notion.py` 会生成 `db_schema.sql`，直接作为 `notion-create-database` 的 `schema` 参数。

## 上传步骤

先 `ToolSearch` 加载 Notion 工具（`notion-create-pages`、`notion-update-page`、`notion-create-database`、`notion-fetch`、`notion-search`）。如果没有 Notion 连接器，告诉用户在 Claude 设置的连接器里连上 Notion；或者退回离线方案：把分册 md 打成 zip，用户在 Notion「导入 → Markdown」手动导入（没有折叠答案和数据库）。

1. **总入口页**：`notion-create-pages`，不指定 parent 会建成工作区私有页面。内容取 00 总览里的考试结构、计划、差异表和"怎么用"，不要把 427 条总清单贴进去（数据库替代它）。记下返回的 page id。
2. **分册页**：父页面 = 总入口页，按 01→09 顺序逐个建（顺序决定 Notion 里的排列）。内容取 `plan.json` 里各册的 `page_md`。
3. **数据库**：放在 01–08 分册页之后、09 之前建，这样它在入口页里排在 09 前面。`notion-create-database`（parent = 入口页，title "知识点进度"，schema = db_schema.sql 内容）。然后用返回的 data_source_id，把每个 `db_rows_K.json`（≤90 行）作为一次 `notion-create-pages` 的 pages 写入。
4. **09 公式速查**：最后建。
5. **章节子页面**：父页面 = 对应分册页，按章顺序建。章节多时并行派子代理，**每个子代理负责一个分册**（保证同一分册内顺序），提示里给出：父页面 id、按顺序的章标题和文件路径、"读文件原文原样上传，不改写内容"。
   - 文件被拆成 `_a/_b/…` 的章：先用 `_a` 建页面，再对同一页面依次 `notion-update-page`（insert_content，追加到末尾）上传 `_b`、`_c`。
   - 子代理在超长内容上容易生成坏 JSON 然后中断。所以分段阈值别调太大（默认 10000 字）；某章失败就派一个新代理只传这一章，不要整册重来。

## Notion Markdown 的坑

| 问题 | 处理 |
|---|---|
| `<字母` 被当成 HTML 标签吞掉（如 `V<Vbi`、`<stdio.h>`） | 转换脚本已转义成 `\<`；手写内容也要注意 |
| `$…$` 会被解析成行内公式 | 正文不用 `$`；公式用 Unicode 上下标（n₀、10¹⁶、√）和 `exp[…]` 写法 |
| `<details>` 不支持 | 折叠用 `<toggle color="green">标题行\n\n内容</toggle>` |
| 引用块里放表格会坏 | 脚本去掉 `> |` 前缀 |
| `**` 在中文标点旁有时不生效、原样显示 | 无害，可忽略；介意的话把粗体两侧留空格 |
| 页面过长上传失败 | 分段上传（见上） |
| 表格紧跟在列表项或段落后面（中间没空行），整张表被并进上一块，显示成一串 `\|` 文字 | 转换脚本已在表格前补空行；已上传的页面用 update_content 把 `<br />\|…` 换回真正的表格 |
| 表格后紧跟的普通文字行（没空行）被吞成表格的多余一行 | 转换脚本已在表格后补空行（后面是列表项时 Notion 不会吞） |
| 单元格里写绝对值 \|V_TP\|、\|βA\|，竖线把一行切成多格，后半行丢失 | 表格里用全角 ｜V_TP｜；转换脚本遇到列数不一致的行会打印 "!!" 警告 |
| 子代理"原样复制"长文本时偶尔改错个别字（实测出现过"涨落"变"涌落"） | 让上传代理上传后 fetch 回来与源文件比对；至少抽查分段上传的章 |

## 上传后的核对（必须做）

1. `notion-fetch` 总入口页：分册顺序 01…08、数据库、09，无重复页面（中断重试最容易造成重复，重复的用 `notion-delete-pages` 删掉前先和用户确认）。
2. 逐个 fetch 分册页：子页面数 = `plan.json` 的章数，顺序一致。
3. 抽查分段上传的章：最后一题的折叠块在；折叠块数 = plan.json 的 `answers`。
4. `notion-query-data-sources` 统计数据库行数 = 知识点总数。
5. 向用户汇报时说清楚哪些核对过、哪些只是抽查。

## 在 Notion 里复习和问答

告诉用户这几种用法：
- **自测**：每章先做典型题，再展开绿色折叠块对答案；数据库里把知识点从"未开始"拖到"学习中/已掌握"，复习一遍"复习次数"+1。
- **筛选视图**：数据库按"重要程度 = ★★★ 且 掌握状态 ≠ 已掌握"建视图，就是冲刺清单。
- **找 Claude 问答**：在对话里说"讲一下第 12 章的压阻效应""按 pn 结再出 5 道选择题""批改我第 5 章第 3 题"。Claude 用 `notion-search` / `notion-fetch` 读对应页面后讲解、出新题或批改；出新题时题型和难度对齐页面里的典型题，答案先不给，等用户作答再批改。
- **Notion AI**（如果用户的工作区有）：在页面里直接问也行，但只能基于页面内容。
